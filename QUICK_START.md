# FinSight Advisor — Quick Start

FinSight Advisor is a role-based financial intelligence platform. It provides ledger upload, semantic grouping, expense categorisation, budget forecasting, and forensic anomaly review.

The application has three parts:

```text
Browser (React + Vite)  →  FastAPI API  →  Supabase PostgreSQL
     localhost:3000          localhost:8000       hosted database
```

Docker is the recommended way to run the project locally. It starts the frontend and backend; Supabase remains the database, so there is no local PostgreSQL container to start.

## Requirements

### Required for the Docker workflow

- Docker Desktop or Docker Engine, with Docker Compose v2.
- A Supabase project and its PostgreSQL connection string.
- Internet access on the first run. Python packages and the Sentence Transformer model are downloaded then.

Check that Docker is available:

```bash
docker --version
docker compose version
```

### Required for the native workflow

- Python 3.12.
- Node.js 22 or newer, with npm.
- A Supabase project and its PostgreSQL connection string.
- A C/C++ build toolchain may be needed by Python packages on some operating systems.

Check the installed versions:

```bash
python3 --version
node --version
npm --version
```

## Configure Supabase and the backend

The backend reads its runtime configuration from `backend/.env`. This file is ignored by Git and must not be committed.

If it does not already exist, create it from the example:

```bash
cp backend/.env.example backend/.env
```

Set at least these values in `backend/.env`:

```env
# Use the exact PostgreSQL URI from your Supabase project.
# If the password has reserved characters, use the URI generated by Supabase.
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/postgres?sslmode=require

# Generate a unique value. Do not use the example value in a deployed app.
SECRET_KEY=replace-with-a-long-random-secret

JWT_ALGORITHM=HS256
JWT_EXPIRATION_HOURS=0.5

ENV=development
DEBUG=True
HOST=0.0.0.0
PORT=8000

# The Docker frontend is served on port 3000.
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000

# Set to True only for an empty development database.
AUTO_SEED_DEMO=True

# Optional: required only for AI-assisted expense-category suggestions.
GEMINI_API_KEY=

# Semantic grouping
SBERT_MODEL=all-MiniLM-L6-v2
SBERT_SIMILARITY_THRESHOLD=0.80

# Forensic analysis thresholds
BENFORD_CHI_SQ_THRESHOLD=3.84
ZSCORE_THRESHOLD=3.0
RSF_UPPER_THRESHOLD=3.0
RSF_LOWER_THRESHOLD=0.1

# Budget forecasting
FORECAST_MONTHS=12
FORECAST_CONFIDENCE_INTERVAL=0.20

# Logging
LOG_LEVEL=INFO

# Rate limiting (reserved for future use)
RATE_LIMIT_ENABLED=False
RATE_LIMIT_REQUESTS_PER_MINUTE=60
```

Generate a secret key with:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

### Gemini configuration

Gemini is optional for ordinary login, ledger upload, grouping, forecasting, and forensic analysis.

- The backend needs `GEMINI_API_KEY` in `backend/.env` when using AI-assisted expense-category suggestions.
- The frontend Presentation Slides feature needs `GEMINI_API_KEY` at build time for its “Listen to Script” narration button.

Set the `GEMINI_API_KEY` value in the backend configuration block when you need backend category suggestions.

For the Docker frontend narration feature, create a root `.env` file next to `docker-compose.yml`:

```env
GEMINI_API_KEY=your-google-ai-api-key
VITE_API_BASE_URL=http://localhost:8000
```

The frontend key is embedded in the browser bundle by the current Vite configuration. Use a restricted development key and do not expose a privileged key in a public deployment.

### Fresh Supabase database

If the Supabase database does not contain the FinSight tables, apply `backend/schema.sql` once through the Supabase SQL Editor or with `psql`:

```bash
psql "YOUR_SUPABASE_DATABASE_URL" < backend/schema.sql
```

The backend also creates and updates its ORM tables on startup. Apply the schema before a first shared or production deployment so the database setup is explicit and reviewable.

## Run with Docker

From the project root, build and start both services:

```bash
docker compose up --build
```

The first build can take several minutes because it installs PyTorch, Sentence Transformers, Pandas, SciPy, and the other backend dependencies. The Dockerfile installs the CPU-only PyTorch build, which avoids downloading unnecessary NVIDIA CUDA libraries. Later builds reuse cached dependency layers unless `backend/requirements.txt`, `frontend/package.json`, or a lockfile changes.

To run the containers in the background:

```bash
docker compose up -d --build
```

Open these addresses after the backend health check succeeds:

| Service | Address |
|---|---|
| Frontend | <http://localhost:3000> |
| API health check | <http://localhost:8000/health> |
| API documentation | <http://localhost:8000/api/docs> |

View logs:

```bash
docker compose logs -f
```

View only backend logs:

```bash
docker compose logs -f backend
```

Stop the containers without removing Docker volumes:

```bash
docker compose down
```

`docker compose down -v` also removes the local Docker volumes used for cached models and optional local data. It does not delete anything in Supabase.

### Rebuild after code changes

The containers copy source files into their images, so source changes require a rebuild:

```bash
docker compose up --build
```

For a frontend-only change:

```bash
docker compose build frontend
docker compose up -d frontend
```

For a backend-only change:

```bash
docker compose build backend
docker compose up -d backend
```

Changing `backend/requirements.txt` causes the Python dependency layer to install again. Changing frontend package files causes `npm ci` to run again. Do not use `--no-cache` unless you need a completely fresh build.

## Run without Docker

Use this workflow when you want Vite hot reload and FastAPI reload during development.

### 1. Start the backend

In one terminal:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

The API is ready when this succeeds:

```bash
curl http://localhost:8000/health
```

### 2. Start the frontend

In a second terminal:

```bash
cd frontend
npm ci
npm run dev
```

Vite serves the frontend at <http://localhost:3000>. The default API base URL is `http://localhost:8000`, so no additional frontend configuration is required for the normal local setup.

To use Gemini narration locally, create `frontend/.env.local`:

```env
GEMINI_API_KEY=your-google-ai-api-key
VITE_API_BASE_URL=http://localhost:8000
```

Restart `npm run dev` after changing a Vite environment file.

## First-use checklist

1. Open <http://localhost:3000>.
2. Log in with a demo account if `AUTO_SEED_DEMO=True` and the database was empty.
3. Choose a department.
4. Upload a CSV, XLS, or XLSX ledger.
5. Run grouping, categorisation, forecasting, or forensic analysis from the dashboard.

The application accepts `.csv`, `.xls`, and `.xlsx` uploads. A ledger must contain these fields, using the listed names or supported aliases:

| Required data | Supported names |
|---|---|
| Transaction date | `transaction_date`, `date`, `txn_date` |
| Description | `description`, `narration`, `details`, `remarks` |
| Chart of account head | `chart_acc_head`, `chart_of_acc_head`, `account_head`, `chart_account_head` |
| Amount or credit | `amount`, `debit`, `debit_amount`, `transaction_amount`, `credit`, `credit_amount` |

## Troubleshooting

### The frontend cannot reach the API

Confirm the backend is healthy:

```bash
curl http://localhost:8000/health
```

For Docker, confirm that `VITE_API_BASE_URL` is `http://localhost:8000` in the root `.env`, then rebuild the frontend:

```bash
docker compose build frontend
docker compose up -d frontend
```

For native development, confirm that `CORS_ORIGINS` includes `http://localhost:3000` and restart the backend.

### Database connection fails

Check that `DATABASE_URL` in `backend/.env` is the Supabase PostgreSQL connection URI, includes `sslmode=require` when required by the selected Supabase endpoint, and has URL-encoded password characters. The Docker services do not provide a local PostgreSQL server.

### Docker reports “no space left on device”

The first backend image is large. Check Docker storage:

```bash
docker system df -v
```

Remove unused build cache:

```bash
docker builder prune
```

If you use Docker Desktop, increase its virtual disk allocation. Avoid `docker compose build --no-cache` unless you are troubleshooting a build issue.

### The first grouping request is slow

The Sentence Transformer model downloads the first time semantic grouping is used. Docker stores this cache in the `model_cache` volume. Leave that volume in place between runs to avoid repeated downloads.

### Gemini category suggestion fails

Add a valid `GEMINI_API_KEY` to `backend/.env`, restart the backend container or development server, and try the category suggestion again.

### Port 3000 or 8000 is already in use

Stop the process using the port, or change the left side of the relevant `ports` mapping in `docker-compose.yml`. For example, map the frontend as `"3001:80"` and then open <http://localhost:3001>.
